# IoT Cyber Threat Intelligence GraphRAG - Evaluator's Guide

Welcome! This guide is written for evaluators and professors to easily run,
verify, and explore the **GraphRAG-Powered IoT Cyber Threat Intelligence Pipeline**.

This project ingests IoT network traffic from the **IoT-23** and **CICIoT2023**
datasets, constructs a Knowledge Graph in Neo4j, generates structural and text
embeddings, and provides an LLM-powered interactive cyber threat explainer.

> **Runs fully locally.** The LLM (threat explanations) runs on **Ollama** and the
> embeddings run on a local **sentence-transformers** model. No cloud API key is
> required for the core pipeline.

> **Zero-Hassle Datasets:** Raw dataset samples are included in the `data/` folder.
> You do **not** need to download gigabytes of data to exercise the pipeline.

---

## Architecture Overview

This project uses **Hexagonal (Ports & Adapters) architecture** for the
swappable I/O layer, with the six processing stages living under `src/services/`:

- **Ports** (`src/ports/`): Abstract interfaces — `LLMPort`, `GraphPort`, `EmbeddingPort`
- **Adapters** (`src/adapters/`): Concrete implementations — `OllamaAdapter`,
  `Neo4jAdapter`, and `Mock*` adapters for testing without external services
- **Core** (`src/core/`): Exception hierarchy, configuration validation, structured errors
- **Services** (`src/services/`): The 6 pipeline stages — data acquisition ->
  feature extraction -> knowledge graph -> embeddings -> GraphRAG -> threat explanation

> **Config note:** The pipeline services read runtime settings from the root
> `config/` package, while the hexagonal adapter/core layer reads from
> `src/core/config.py`. Both are intentional today; see
> [docs/decisions/0007-dual-config-coexistence.md](docs/decisions/0007-dual-config-coexistence.md).

For all design decisions, see [docs/decisions/](docs/decisions/).

## Step 1: Environment Setup

This project requires **Python 3.10+**.

1. **Open a terminal** (PowerShell or Command Prompt) inside this project folder.
2. **Create and activate a virtual environment:**
   ```powershell
   python -m venv venv
   .\venv\Scripts\activate
   ```
3. **Install the dependencies:**
   ```powershell
   pip install -r requirements.txt
   ```

---

## Step 2: Neo4j Database Setup (Local)

The full Knowledge Graph is large, so it runs against a local Neo4j database.

1. Download and install [Neo4j Desktop](https://neo4j.com/download/).
2. Open Neo4j Desktop and click **Create Instance**.
3. Configure the instance:
   - **Name:** `IoT Cyber KG` (or any name)
   - **Password:** `password` *(matches the default in `.env.example`)*
4. Click **Start** to run the database locally.

### Optional: Neo4j Aura Cloud

You can instead use Neo4j's managed cloud service:

1. Go to [Neo4j Aura](https://neo4j.com/cloud/aura/) and create a free instance.
2. Update `.env` with your cloud URI (e.g. `neo4j+s://<id>.databases.neo4j.io`).

---

## Step 3: Local LLM (Ollama) Setup

Threat explanations are generated by a **local** Ollama model — no API key needed.

1. Install [Ollama](https://ollama.com/download) and start the service:
   ```powershell
   ollama serve
   ```
2. Pull the default model:
   ```powershell
   ollama pull gemma:4b
   ```

---

## Step 4: Configuration

1. Copy the example env file:
   ```powershell
   copy .env.example .env
   ```
2. The defaults work out of the box for a local setup:
   ```env
   NEO4J_URI=bolt://localhost:7687
   NEO4J_USER=neo4j
   NEO4J_PASSWORD=password

   OLLAMA_API_URL=http://localhost:11434/api
   OLLAMA_MODEL=gemma:4b
   ```

Text embeddings use the local `all-MiniLM-L6-v2` model (384-dim) via
`sentence-transformers`; it downloads automatically on first run (~90MB) and then
works offline. `GOOGLE_API_KEY` is **optional** and not used by the core pipeline.
See [.env.example](.env.example) for all options.

## Step 5: Verify Installation

Before running the full pipeline, verify the core architecture is sound:

```powershell
python tests/smoke/test_core.py
```

Expected output:
```
Results: 5 passed, 0 failed
```

This validates that all modules import, the exception hierarchy is correct, port
abstractions are enforced, adapters honor their contracts, and the mock adapters
work without any external services.

---

## Step 6: Run the Full Pipeline

To execute the complete pipeline:

1. Run **`run_evaluator.bat`** from the project folder.
2. When prompted, choose whether to build the Knowledge Graph from scratch.

The script automates the remaining stages:
- **Stage 1:** Loads/validates the IoT dataset samples
- **Stage 2:** Extracts network features and preprocesses data
- **Stage 3:** Ingests data into Neo4j to build the Knowledge Graph
- **Stage 4:** Generates graph + text embeddings
- **Stage 5:** Initializes the vector store for semantic search
- **Stage 6:** Boots the **Interactive Threat Analyst CLI**

---

## Step 7: Interactive GraphRAG Evaluation

Once the graph is built, you are dropped into the interactive terminal to ask
natural-language questions over the network data. Try:

- *"Which devices are exhibiting Mirai botnet behavior, and what protocols are they using?"*
- *"Summarize the most common attack types targeting port 80."*
- *"Are there any devices initiating DDoS attacks? Map them to the MITRE ATT&CK framework."*

## Visualizing the Graph (Optional)

Inspect the Knowledge Graph directly in Neo4j Desktop:

1. Open the **Query** tool.
2. Ensure the database dropdown is set to `iot` (not `system`).
3. Run:
   ```cypher
   MATCH path=(src:Device)-[:INITIATES]->(f:Flow)-[:TARGETS]->(dst:Device)
   WHERE f.label <> 'Benign'
   RETURN path LIMIT 50
   ```

## Project Structure

- `src/ports/`, `src/adapters/`, `src/core/`: Hexagonal I/O layer (interfaces,
  implementations, exceptions/config).
- `src/cli/main.py`: Interactive threat-analyst CLI.
- `src/services/data_acquisition/`: Loaders for IoT-23 and CICIoT2023.
- `src/services/feature_extraction/`: Pandas-based normalization and feature engineering.
- `src/services/knowledge_graph/`: Cypher ingestion scripts and schema definitions.
- `src/services/graph_embeddings/`: NetworkX/Neo4j analytics, `node2vec` structural
  embeddings, and local `sentence-transformers` text embeddings.
- `src/services/graphrag/`: Vector storage and semantic retrieval logic.
- `src/services/threat_explanation/`: Ollama LLM integration, prompt engineering, grounding.
- `src/services/evaluation/`: Ablation, baselines, and LLM-comparison evaluation.
- `config/`: Runtime settings consumed by the pipeline services.
- `tests/`: Smoke, unit (per stage), and integration tests.
