# Chapter 4: Results and Evaluation

## 4.1 System Architecture and Experimental Setup

The evaluation of the CyberGuard system was conducted on consumer-grade edge hardware to validate the feasibility of deploying advanced Graph Retrieval-Augmented Generation (GraphRAG) pipelines in resource-constrained environments. 

### 4.1.1 Hardware Specifications
*   **Processor:** Intel Core i5-12450HX
*   **Memory (RAM):** 16 GB System Memory
*   **Graphics Processing Unit (GPU):** NVIDIA RTX 3050 (6 GB VRAM)
*   **Storage:** Solid State Drive (SSD)

### 4.1.2 Software Stack
*   **Graph Database:** Neo4j Community Edition
*   **Local LLM Engine:** Ollama Framework
*   **Language Model:** Google Gemma 4 (7.2B Parameters, Extended Context Window)
*   **Data Ingestion:** Python 3.10, Pandas, Py2Neo

Unlike traditional cloud-based SIEM (Security Information and Event Management) solutions that transmit highly sensitive packet capture data to external APIs, this architecture emphasizes **Data Privacy and Edge Computing**. The entire parsing, graph generation, embedding, and inference pipeline is executed 100% offline. 

## 4.2 Edge AI Inference Latency Metrics

A critical component of evaluating a Cyber Threat Intelligence (CTI) pipeline is the speed at which it can autonomously analyze and report on network anomalies. To evaluate the latency of the Gemma 4 (7.2B) model operating on the constrained RTX 3050 (6GB VRAM), we recorded the end-to-end response times across five distinct GraphRAG query profiles.

Because the model size (7.2GB) exceeds the available physical VRAM (6GB), the system utilized dynamic VRAM-to-System-RAM offloading. 

| Query Profile | Example Query | Retrieval Strategy | Inference Latency (Seconds) |
| :--- | :--- | :--- | :--- |
| **Empty Node Search** | `device 192.168.1.1` | Direct Cypher Match (Cache Miss) | 3.64 s |
| **Attack Vector Analysis** | `attack DDoS-SynonymousIP_Flood` | Knowledge Graph Traversal | 149.69 s |
| **MITRE ATT&CK Mapping** | `mitre` | Cypher + Vector Embeddings | 139.76 s |
| **Dataset Comparison** | `compare` | Aggregated Graph Cypher | 187.35 s |
| **Custom Analytical Query** | `investigate Torii vs Hajime` | Deep Hybrid RAG Retrieval | 181.30 s |

**Analysis of Latency Findings:**
The results demonstrate that while VRAM constraints introduce an offloading penalty, the system consistently returns comprehensive, multi-page analytical reports within an average of **2.5 to 3.1 minutes**. In the context of a Tier-1 SOC (Security Operations Center) Analyst, manually pulling PCAP logs, writing SQL queries, and drafting an incident report takes significantly longer (often hours). Therefore, a 3-minute autonomous generation cycle is highly acceptable for automated threat intelligence.

## 4.3 Hallucination Mitigation and Factuality

A fundamental flaw in utilizing Generative AI for cybersecurity is "hallucination"—the generation of mathematically incorrect data or the fabrication of attack signatures. The CyberGuard pipeline mitigates this by restricting the LLM's generative scope strictly to the context retrieved from the Neo4j Knowledge Graph.

To mathematically prove the elimination of hallucinations, a programmatic testing suite (`evaluate_llm_hallucinations.py`) was executed against the generated reports.

*   **IP Groundedness (100.0%):** A strict regex parsed every IPv4 address generated by the LLM. 100% of the generated IPs existed within the `device_profiling` graph context. Zero fake IP addresses were generated.
*   **Context Relevance (100.0%):** The attacks discussed by the LLM (e.g., `Mirai-greeth_flood`, `DDoS-SYN_Flood`) were mapped back to the raw Cypher query outputs. The LLM achieved 100% adherence to the provided data.
*   **Refusal to Fabricate Data:** During testing, the system was queried to compare the internal command-and-control structures of the *Torii* and *Hajime* botnets based on the graph data. The system successfully recognized that the specific data did not exist in the database and explicitly refused to hallucinate fake metrics, instead offering a theoretical comparison based on general cybersecurity knowledge. 

## 4.4 Graph Retrieval Advantages over Traditional RAG

Traditional RAG systems rely purely on Vector Embeddings (cosine similarity) to retrieve text chunks. In cybersecurity, this fails when attempting to understand the relational topology of an attack (e.g., "Which IPs did this compromised node communicate with?"). 

The implementation of GraphRAG proved superior in two distinct ways:
1.  **Topological Context:** The Cypher retrieval engine allowed the LLM to "see" the network. By structuring data relationally (`(Device)-[:INITIATES]->(Flow)-[:CLASSIFIED_AS]->(AttackType)`), the LLM accurately mapped multi-vector kill chains to the MITRE ATT&CK framework (e.g., identifying T1498 - Network Denial of Service based on 3,526,052 fragmented flows).
2.  **Mitigation of Cartesian Explosions:** Initial testing revealed database hang states when querying highly centralized nodes (e.g., the `0.0.0.0` broadcast address) due to Cartesian product explosions in Neo4j. By optimizing the Cypher queries with sequential `WITH` clauses, the query execution time was reduced from an infinite timeout to under 2 seconds, ensuring the LLM was fed context without database deadlocks.

## 4.5 Comparative Dataset Analysis (CICIoT2023 vs IoT-23)

The GraphRAG system autonomously performed a comparative analysis between the two foundational datasets, revealing critical insights into the evolution of IoT malware.

*   **CICIoT2023 (The External Attack Surface):** The system mapped 3,526,052 flows heavily weighted towards volumetric availability attacks (DDoS/DoS). Crucially, it identified the persistent presence of malware families like **Mirai** (105,151 flows), indicating a shift towards exploiting embedded system flaws for large-scale botnet propagation.
*   **IoT-23 (The Internal Baseline):** In contrast, the system correctly identified IoT-23 as an overwhelmingly benign baseline dataset. 

The successful autonomous comparison of these datasets proves the system's viability as a high-level strategic intelligence tool, capable of synthesizing disparate data lakes into cohesive cybersecurity trends without human intervention.
